# 02 — DEPLOYMENT GUIDE

**Deployment Target:** `jadai.dev`
**Frontend:** Cloudflare Pages (static SPA, $0)
**API:** Render Free — `api.jadai.dev` ($0)
**Database:** Supabase PostgreSQL (free tier)
**Payments:** Paystack (per-transaction only)

> Vercel is disqualified: Paystack is a commercial gateway and the Vercel Hobby plan forbids commercial use. This architecture is Cloudflare Pages + Render Free instead.

---

## 1. Domain Setup (Namecheap → Cloudflare)

1. Create a Cloudflare account, add `jadai.dev`.
2. At Namecheap, change the domain's nameservers to the two Cloudflare assigned nameservers.
3. DNS records in Cloudflare:

| Type | Name | Target |
|---|---|---|
| CNAME | `@` | `<project>.pages.dev` (proxied) |
| CNAME | `www` | `jadai.dev` (proxied) |
| CNAME | `api` | `<service>.onrender.com` (proxied) |

4. Create a Page Rules / redirect so `api.jadai.dev` always resolves to the Render service (the `api` CNAME handles this).

---

## 2. Frontend: Cloudflare Pages

1. Push the repository to GitHub.
2. Cloudflare Dashboard → **Workers & Pages → Create → Pages → Connect to Git**.
3. Build settings:
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - **Node version:** set `NODE_VERSION=22` (engines require >= 22).
4. Deploy. First build produces the static SPA.
5. Custom domain: add `jadai.dev` + `www.jadai.dev` to the Pages project.
6. `public/_redirects` (shipped with the build) proxies:
   ```
   /api/*   https://api.jadai.dev/api/:splat   200
   /s/*     https://api.jadai.dev/s/:splat     200
   ```

---

## 3. API: Render Free

`render.yaml` at the repo root defines the service:

```yaml
buildCommand: npm ci
startCommand: npm run start      # tsx server.ts
healthCheckPath: /api/health
SERVE_STATIC: "0"                # Pages serves the SPA
```

1. Render → **New → Web Service** → connect the repo (render.yaml is auto-detected).
2. Set the sensitive env vars in the dashboard (see §5).
3. Render assigns `<service>.onrender.com` — point the `api` DNS record at it.
4. Set `NEXT_PUBLIC_APP_URL=https://jadai.dev` so cookies, CORS, and return URLs are correct.

**Alternative (no Pages):** set `SERVE_STATIC=1` on Render and point all DNS at the single service — the SPA is served by Express from `dist/`.

## 4. Database: Supabase

1. Create a free project at [supabase.com](https://supabase.com).
2. SQL Editor → paste all of `lib/supabase/schema.sql` → **Run**.
   Idempotent (`CREATE TABLE IF NOT EXISTS`): 34 tables, RLS policies, `is_admin()`, updated_at triggers, module seeds. Re-run safely after schema updates.
3. Copy into Render env vars:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (server only — never ship to the client)

### Storage buckets (dashboard → Storage)

| Bucket | Access |
|---|---|
| `avatars` | public read / auth write, 5MB |
| `portfolio` | public read / admin write, 10MB |
| `templates` | private / admin write, 50MB |
| `book-of-lies` | public read / admin write, 20MB |

## 5. Environment Variables (Render → Environment)

Complete list — also mirrored in `.env.example` with placeholder values.

| Key | Required? | Purpose |
|---|---|---|
| `NODE_ENV=production` | yes | production behavior |
| `SERVE_STATIC=0` | yes (Pages setup) | API-only mode (Pages serves SPA) |
| `SESSION_SECRET` | yes | ≥32 chars — admin HMAC signing (auto-generated by render.yaml) |
| `CRON_SECRET` | yes | guards `/api/cron/*` (auto-generated by render.yaml) |
| `ADMIN_EMAIL` | yes | admin identity |
| `ADMIN_PASSWORD_HASH` | yes | `npm run gen:admin-hash` output |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | yes | database (client-bundle) |
| `SUPABASE_SERVICE_ROLE_KEY` | yes | server-side database writes |
| `PAYSTACK_SECRET_KEY` / `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY` | yes (payments) | live: `sk_live_…` / `pk_live_…` |
| `GROQ_API_KEY` | yes (AI) | **primary AI provider** — console.groq.com/keys; serves all text AI |
| `OPENAI_API_KEY` | no | secondary AI — **only works with active credits**; otherwise an escalating breaker parks it and Groq takes over |
| `GEMINI_API_KEY` | no | tertiary AI failover |
| `NEXT_PUBLIC_GIPHY_API_KEY` | no | GIF search in PRIME chat (developers.giphy.com — free). Without it, GIF search shows an honest "key required" message; emojis still work |
| `FAL_KEY` / `HF_KEY` | no | paid image-provider fallbacks — image generation already works with **zero keys** via Pollinations free tier (1 image / 45s per IP; server retries once and returns honest partial notes) |
| `NEXT_PUBLIC_APP_URL=https://jadai.dev` | yes | CORS, cookies, return URLs |
| `NEXT_PUBLIC_APP_NAME` | no | brand string |
| `CORS_ORIGINS` | no | override (defaults to `NEXT_PUBLIC_APP_URL`) |
| `GOOGLE_PSI_API_KEY` | no | PageSpeed Insights diagnostics |
| `PORT` | no | server port (default 3000) |
| `DISABLE_HMR` | no | disable Vite HMR/file-watching (AI Studio) |

> Client-bundle keys are the `NEXT_PUBLIC_*` ones — they are injected by `vite.config.ts` `define`. Everything else is server-only.

## 5b. Persistent Data (`DATA_DIR`) — READ BEFORE LAUNCH

The server keeps **filesystem stores** under a single data directory, resolved by
`lib/data/dataDir.ts`:

| Path (under the data dir) | Contents |
|---|---|
| `chat-sessions.json` | PRIME chat history (sessions + messages) |
| `artifacts.json` | generated artifacts (websites/docs/sheets) |
| `uploads/<builderId>/` | uploaded files (up to 100MB each) |
| `rag/` + related | RAG index built from uploads (auto-used in PRIME answers) |
| memory / entitlements / signal / hub / template stores | user state, Pro+ entitlements, radar data |

**Resolution rule:**
- `DATA_DIR` env var set → that path (created on demand) is used.
- Unset → `<cwd>/data` (local dev default, unchanged).

**`render.yaml` already wires this up:** a 1GB disk mounted at `/var/data` plus
`DATA_DIR=/var/data`, so chat history, artifacts, uploads, and the RAG index
**survive redeploys and restarts**.

> ⚠️ Render **disks require the Starter plan ($7/mo)**. If you stay on Free:
> delete the `disk:` block **and** the `DATA_DIR` env var from `render.yaml` —
> everything still works, but `./data` resets on every redeploy.

Local override example (test persistence on any machine):
```
DATA_DIR=/var/data npm run dev
```

Uploads consume disk space (`100MB × users`) — grow `sizeGB` in `render.yaml` as needed.

## 6. Payments: Paystack

1. Register at [paystack.com](https://paystack.com); enable international cards.
2. **Settings → API Keys & Webhooks:**
   - Secret Key → `PAYSTACK_SECRET_KEY`
   - Public Key → `NEXT_PUBLIC_PAYSTACK_PUBLIC_KEY`
   - Webhook URL: **`https://api.jadai.dev/api/paystack/webhook`**
3. Plan codes in `lib/paystack/index.ts` (`STARTUP_PAYSTACK_PLANS`) must match your Paystack plans.
4. Test first with `sk_test_` / `pk_test_` — checkout redirects to Paystack sandbox.

## 8. Zero-Cost Guarantee

- **Cloudflare Pages:** free, unlimited bandwidth.
- **Render Free:** free web service (sleeps after inactivity — UptimeRobot pings keep it warm).
- **Supabase Free:** 500MB DB, 5GB storage, 50k MAU.
- **Groq:** free tier serves all text AI (primary). OpenAI optional (needs paid credits). Gemini optional.
- **Image generation:** Pollinations free tier works with no key (1 image / 45s per IP — server retries and returns honest partials). Optional `FAL_KEY` / `HF_KEY` paid fallbacks.
- **Paystack:** ₦0 setup — only per-transaction fees.
- **cron-job.org / UptimeRobot:** free tiers.

First steady-state cost: domain (~$12/year) + transaction fees after your first sale.

## 9. Pre-Launch Checklist

- [ ] `lib/supabase/schema.sql` re-run (picks up `ai_memories`, `ai_messages`, `contact_submissions`, `dream_forge_intakes`).
- [ ] `ADMIN_PASSWORD_HASH` generated and set.
- [ ] Nameservers moved; three DNS records live.
- [ ] Pages build green; `curl https://jadai.dev/api/health` → 200 via Render.
- [ ] Paystack **live** keys set (`sk_live_` / `pk_live_`) and webhook fires (dashboard → Webhooks log).
- [ ] `GROQ_API_KEY` set and verified (`GET /api/ai/status` → `groq.configured: true`).
- [ ] `OPENAI_API_KEY` set **only if** OpenAI credits are topped up (otherwise leave unset — Groq serves everything; the breaker auto-resumes when credits return).
- [ ] **Disk decision:** Starter plan+ → keep `disk:` + `DATA_DIR` in render.yaml (data persists). Free plan → delete both blocks (data resets each deploy). See §5b.
- [ ] Optional: `NEXT_PUBLIC_GIPHY_API_KEY` set for GIF search.
- [ ] Both cron jobs saved with the secret header.
- [ ] Smoke test: register → subscribe (test key) → entitlement active; PRIME chat answers offline-labelled when keys are absent.
- [ ] Smoke test new features: upload a PDF in PRIME chat → ask about its content; generate an artifact → open its preview URL; generate an image (Pollinations, no key needed).
